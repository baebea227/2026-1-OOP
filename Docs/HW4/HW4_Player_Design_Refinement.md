# HW4 Player Design Refinement

| Before 단계의 Class 등 설계 classifier | After 단계의 Class 등 설계 classifier(s) | 적용한 설계 개념 (GRASP, Design Pattern 적용) | Architecture Design Rationale (본인이 생각하는 합리성) | NFR 와 QA 에 대한 영향 분석 |
| --- | --- | --- | --- | --- |
| `PlayerMovement` | `PlayerMovement`, `IPushInteractionStrategy`, `HeavyPushInteractionStrategy`, `LightPushInteractionStrategy` | GRASP: Controller, Polymorphism, High Cohesion / Design Pattern: Strategy | 기존 `PlayerMovement`가 일반 오브젝트 push와 heavy object 협동 push를 직접 분기했다. 변경 후 push 대상에 따라 달라지는 알고리즘을 strategy classifier로 분리하여 이동 흐름과 push 정책을 구분했다. | Maintainability 향상: push 정책 변경 영향 범위가 축소된다. Modifiability 향상: 새로운 push 전략 추가가 쉽다. Reliability 유지: heavy 우선, light 후순위의 기존 판정 순서를 유지한다. |
| `PlayerInputHandler` | `PlayerInputHandler`, `PlayerNetworkInput` | GRASP: Controller, Low Coupling, Information Expert / Design Pattern: Adapter | Unity Input System의 입력 표현과 Fusion `NetworkInput` 전달 형식은 서로 다르다. `PlayerInputHandler`가 local input action을 `PlayerNetworkInput`으로 변환하여 movement/grab controller가 입력 장치 세부사항에 직접 의존하지 않게 한다. | Interoperability 향상: 입력 시스템과 네트워크 입력 구조 사이의 변환 지점이 명확하다. Testability 향상: `PlayerNetworkInput` 기준으로 movement/grab 동작을 확인할 수 있다. |
| `PlayerGrabHandler` | `PlayerGrabHandler`, `GrabbableObject`, `HeavyObject` | GRASP: Controller, Low Coupling / Design Pattern: Facade | `PlayerGrabHandler`가 grab, drop, throw, interact 요청의 진입점 역할을 한다. 클라이언트 입력은 세부 RPC, reach validation, hold point 계산을 직접 다루지 않고 facade를 통해 요청한다. | Understandability 향상: player interaction 흐름을 한 classifier에서 추적할 수 있다. Reliability 향상: authority 검증과 거리 검증을 facade 내부에서 일관되게 수행한다. |
